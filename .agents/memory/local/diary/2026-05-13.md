## ssh-key-deploy

- Сделан `ssh-key-deploy/deploy_ssh_key.py` — массовое прописывание публичного SSH-ключа на Windows-хостах из inventory.
- Транспорт — SSH через paramiko (с парольной авторизацией). На удалённом хосте запускается PowerShell через `powershell -EncodedCommand <base64>` (обходит DefaultShellCommandOption и проблемы с эскейпами).
- Логика на хосте: проверка членства в `BUILTIN\Administrators` через SID → файл `administrators_authorized_keys` (для админа) или `~\.ssh\authorized_keys` (для юзера) → идемпотентное добавление + `icacls` для прав.
- Изначально начал писать на PowerShell, потратил время на BOM/эскейпы (PS 5.1 без BOM читает .ps1 в cp1251 и парсер ломается на кириллице). Юзер: "PowerShell слишком проблемный, пользуйся питоном". Переписал на Python.
- Потом юзер уточнил: "придется все-таки на powershell написать этот скрипт... но py давай оставим тоже". Итог: обе реализации рядом (Deploy-SshKey.ps1 + deploy_ssh_key.py), общий config.yaml.example. См. [../topics/toolchain-preference.md](../topics/toolchain-preference.md) — обновил под "PS основной, Python допускается рядом".
- Конкретные грабли PowerShell:
  - PS 5.1 без UTF-8 BOM на .ps1 с кириллицей → парсер видит cp1251, ломается на двойных кавычках. Симптом: `[Parser]::ParseFile` показывает ошибки в случайных местах (типа `Sort-Object { ... '$1.$2.$3.$4' }`), а `[scriptblock]::Create` показывает правильное место.
  - `$role:` ломает парсер — `:` после `$var` — это scope-префикс (`$env:`, `$global:`). Решение — `${role}:`.
  - Литеральная here-string `@'...'@` + `.Replace('__X__', $val)` вместо `@"..."@` с тоннами `` ` ``-эскейпов.
- Финальная PS-версия — на латинице (русский только в логах), плюс дописывание BOM сразу после Write. Парсится OK, на 121 хосте инвентаря собирается удалённая команда.
